# DevBridge - 개발자와 프로젝트를 잇는 매칭 플랫폼

- **서비스 소개**: 사이드 프로젝트를 함께할 팀원을 찾는 개발자와 팀 리더를 연결하는 매칭 플랫폼입니다. 지원자는 포지션·관심 분야로 매칭을 신청하고 추천 프로젝트에 참여를 요청합니다. 팀 리더는 모집 공고를 등록하고 진행 방식별로 확인합니다.
- **GitHub 저장소**: https://github.com/chltj/uiuxprogramming
- **배포된 웹페이지 (GitHub Pages)**: https://chltj.github.io/uiuxprogramming/

## ★ 12주차: 재사용 가능한 UI 컴포넌트 (탭 · 아코디언 · 모달)

### 구현한 컴포넌트 한눈에 보기
| 컴포넌트 | 위치 | 사용 목적 | 동작 방법 | 현재 상태 표시 |
| :--- | :--- | :--- | :--- | :--- |
| **탭** (기존 기능 개선) | 프로젝트 둘러보기 | 프론트엔드 / 백엔드 / AI·데이터 분야별 모집 프로젝트를 한 영역에서 바꿔 보기 | 탭 클릭 또는 ← → Home End 키 → 해당 패널만 표시 | 선택된 탭: 파란 배경·밑줄 + `aria-selected="true"` |
| **아코디언** (새로 추가) | 이용 방법 > 자주 묻는 질문 | 서비스 이용 중 자주 생기는 질문 4개의 답변을 필요할 때만 펼쳐 보기 | 질문 클릭 또는 Enter·Space → 답변 열기/닫기, ↑ ↓ Home End 키로 질문 사이 이동 | “＋ 펼치기” ↔ “− 접기” 문구, 열린 항목은 하늘색 배경·왼쪽 파란 선 + `aria-expanded` |
| **모달 ①** 공고 상세 (새로 추가) | 팀원 모집 등록 > 내가 등록한 모집 공고 | 목록에는 요약만 보이는 공고의 소개·포지션·연락처를 자세히 보고 이메일로 지원 | 각 공고의 [상세 보기] → 창 열림, ✕ / [닫기] / 어두운 배경 클릭 / Esc로 닫기 | 창 열림 + 뒤 화면 어둡게, 열기 버튼 `aria-expanded="true"` |
| **모달 ②** 삭제 확인 (기존 기능 개선) | 내가 등록한 모집 공고 | [저장된 공고 모두 삭제]를 누르자마자 지워지던 것을, 개수를 보여 주고 한 번 더 확인 | [취소] → 아무것도 지우지 않고 닫힘, [공고 모두 삭제] → 삭제 후 닫힘 | “내가 등록한 모집 공고 3개가 삭제되며…” 문구 + ⚠️ 제목 |

### 재사용 구조
- **HTML은 정해진 클래스·속성만 붙이면 동작합니다.**
  - 탭: `role="tablist"` + `data-tabs`
  - 아코디언: `.accordion[data-accordion]` > `.accordion-item` > `.accordion-trigger`(버튼) + `.accordion-panel`
  - 모달: `.modal` > `.modal-backdrop` + `.modal-dialog`(`.modal-header` / `.modal-body` / `.modal-footer`)
  - 같은 모달 구조로 창 두 개(상세 보기, 삭제 확인)를 만들었습니다. 새 창이 필요하면 HTML만 복사하면 됩니다.
- **JavaScript 공통 함수** (`script.js` 맨 위 “12주차: 재사용 UI 컴포넌트” 영역)

  | 함수 / 처리 | 하는 일 | 사용하는 곳 |
  | :--- | :--- | :--- |
  | `initTabs(tablist)` | 탭 선택, 패널 전환, 방향키 이동 | 페이지의 모든 `[data-tabs]` |
  | `initAccordion(root)` / `setAccordionItem(trigger, open)` | 열기·닫기, 상태 문구 변경, 방향키 이동. `data-accordion="single"`로 바꾸면 하나만 열리는 방식 | 페이지의 모든 `[data-accordion]` |
  | `openModal(modal, trigger)` / `closeModal(returnFocus)` | 열기·닫기, 배경 비활성(`inert`), 초점 이동과 복귀 | 상세 보기 모달, 삭제 확인 모달 |
  | `[data-modal-close]` 공통 이벤트 | ✕, [닫기], [취소], 어두운 배경 어디를 눌러도 같은 방식으로 닫음 | 모든 모달 |
  | `getRovingIndex(key, index, length)` | 방향키 → 다음 위치 계산 (끝에서 처음으로 순환) | 탭, 아코디언 |
  | `renderSummaryRows(container, info)` | 항목명–값 요약 표 그리기 | 공고 등록 결과 화면, 공고 상세 모달 |
- **CSS 공통 클래스** (`style.css` “12주차: 재사용 UI 컴포넌트 공통 스타일” 영역): `.accordion-*`, `.modal-*`, `.small-btn`. 버튼은 기존 `.btn` `.primary-btn` `.secondary-btn` `.danger-btn`을 재사용했습니다.

### 접근성 적용 (11주차 내용 반영)
- **키보드 조작**
  - 탭: ← → Home End 키로 이동합니다. 선택된 탭만 Tab 순서에 들어갑니다.
  - 아코디언: Enter·Space로 열고 닫고, ↑ ↓ Home End 키로 질문 사이를 이동합니다.
  - 모달: Esc로 닫습니다. Tab·Shift+Tab은 창 안에서만 돕니다(초점 가두기). 뒤 페이지는 `inert`로 초점이 들어가지 않습니다.
- **초점 이동**
  - 상세 모달을 열면 ✕ 버튼에 초점이 갑니다.
  - 삭제 확인 창에서는 실수로 지우지 않도록 [취소]에 먼저 초점이 갑니다.
  - 창을 닫으면 그 창을 연 버튼으로 초점이 돌아갑니다. 모두 삭제한 뒤에는 삭제 버튼이 사라지므로 목록 제목으로 이동합니다.
- **초점 표시**: 11주차의 3px 파란 테두리를 그대로 적용했습니다. 아코디언 버튼은 테두리가 잘리지 않게 안쪽에 표시합니다.
- **명확한 이름**
  - 각 [상세 보기] 버튼은 “‘캠퍼스 중고거래 모바일 앱’ 상세 보기”처럼 공고명을 포함합니다.
  - ✕ 버튼은 “공고 상세 창 닫기”, 지원 링크는 “‘공고명’ 팀 리더에게 이메일로 지원하기”로 읽힙니다.
- **역할 전달**
  - 상세 창은 `role="dialog"`, 삭제 확인 창은 `role="alertdialog"`입니다. 둘 다 `aria-modal`, `aria-labelledby`, `aria-describedby`를 붙였습니다.
  - 아코디언 패널은 `role="region"`으로 질문 버튼과 연결했습니다.
- **모바일(480px 이하)**: 모달이 화면 아래에서 올라오는 시트 형태로 바뀌고, 하단 버튼이 넓어집니다.

## ★ 11주차: 웹 접근성 개선

### 점검 방법
- **색 대비**: 페이지의 모든 글자에 대해 글자색과 실제 배경색의 명도 대비를 계산했습니다. 기준은 WCAG 2.1 AA(일반 글자 4.5:1, 큰 글자 3:1)이고, 오류·빈 결과·요청서 등 숨겨진 상태 화면도 펼쳐서 점검했습니다.
  - 개선 전: 기준 미달 **34곳**
  - 개선 후: **0곳**
- **키보드**: 마우스 없이 Tab, Shift+Tab, Enter, 방향키, Esc로 매칭 신청 → 추천 프로젝트 참여 요청 → 요청 취소 → 모집 공고 등록 → 필터 선택까지 진행하며 초점 위치를 확인했습니다.
- **구조**: 모든 입력의 라벨 연결, 이름 없는 버튼·링크, 이미지 alt, 제목(h1~h3) 단계 건너뜀을 점검했습니다.

### 개선 전 → 개선 후
| # | 영역 | 개선 전 | 개선 후 |

| 8 | **오류 메시지** | "희망 포지션과 관심 프로젝트 분야를 모두 선택해 주세요."처럼 무엇이 빠졌는지 구분 없음. 초점 이동과 `aria-invalid` 없음 | **빠진 항목만 이름으로 안내**: "선택하지 않은 항목이 있습니다: 관심 프로젝트 분야. 목록을 열어 하나씩 골라 주세요." 이메일은 "비어 있습니다"와 "형식이 올바르지 않습니다 (@와 도메인 포함)"를 구분. **첫 오류 칸으로 초점 이동**, `aria-invalid="true"`, 오류 문구를 `aria-describedby`로 연결 |

### 그대로 유지한 부분 (이미 적용되어 있던 것)
- 서비스 소개 이미지 alt: "DevBridge 대시보드를 화면에 띄우고 팀원 매칭과 프로젝트 기회를 논의하고 있는 개발팀의 모습"
- 모든 입력 요소의 `label` 연결(점검 결과 누락 0개), `html lang="ko"`, `header/nav/main/footer` 구조
- 9주차 폼의 ✔/✖ 기호와 문구, 10주차 필터의 ✔ 표시와 `aria-pressed`, 메뉴의 `aria-current`, 모바일 메뉴의 `aria-expanded`

### 확인 순서 (키보드만 사용)
1. 페이지를 열고 **Tab** → 왼쪽 위에 [본문 바로가기]가 나타남 → **Enter**로 본문 이동
2. **Tab**으로 "프로젝트 둘러보기" 탭에 도착 → **→ / ←** 키로 탭 전환
3. 매칭 신청 1단계에서 아무것도 고르지 않고 [다음 단계로]에서 **Enter** → 빠진 항목 안내와 함께 포지션 선택칸으로 초점 이동
4. 값을 고르고 **Enter** → 2단계 제목으로 초점 이동, 단계 표시에 "✓ (완료)"와 "(현재 단계)" 표시
5. 이메일을 `dev@`로 입력 → 형식 오류 안내, 이메일 칸으로 초점
6. 4단계까지 완료 → [모든 분야 프로젝트 보기] → 카드의 [참여 요청하기] → 요청서 작성 → [참여 요청 보내기] → 성공 안내로 초점
7. [요청 취소] → [네, 취소합니다] / [요청 유지]로 초점이 이어지는지 확인
8. **Shift+Tab**으로 되돌아가며 초점 테두리가 항상 보이는지 확인

## ★ 10주차: 메뉴 이동 · 현재 위치 표시 · 목록 필터 · 모바일 메뉴

### 이번 주 추가·수정한 기능
- **주요 메뉴 재구성**: `nav > ul > li` 구조에 브랜드(DevBridge)와 메뉴 7개를 두고, 메뉴 이름을 이동할 섹션 제목과 맞췄습니다. 예: "프로젝트 탐색" → "프로젝트 둘러보기", 섹션 제목 "팀원 매칭 원스톱 신청" → "매칭 신청 (팀원 매칭 원스톱 신청)".
- **현재 위치 표시**: 지금 화면에 보이는 섹션의 메뉴에 배경색과 밑줄(모바일은 왼쪽 막대)을 표시하고 `aria-current="location"`을 붙입니다. 다른 메뉴에서는 속성을 제거합니다.
- **목록 필터**: 9주차의 "내가 등록한 모집 공고" 목록에 **진행 방식 필터**(전체 / 온라인 / 오프라인 / 온·오프라인 혼합)를 추가했습니다. 결과 수 안내와 두 가지 빈 결과 안내를 넣었습니다.
- **모바일 메뉴**: 768px 이하에서는 메뉴가 접히고 [☰ 메뉴 열기] 버튼으로 펼칩니다.

### 메뉴별 목적지
| 메뉴 | 이동 위치 (`href`) | 현재 위치로 표시되는 영역 |
| :--- | :--- | :--- |
| 서비스 소개 | `#about` | 첫 화면(`#hero`), 서비스 소개, 주요 기능 |
| 프로젝트 둘러보기 | `#explore` | 모집 중인 프로젝트 둘러보기 (탭) |
| 이용 방법 | `#how-to-use` | 이용 방법 |
| 매칭 신청 | `#matching-flow` | 4단계 매칭 신청 위저드 (7주차) |
| 추천 프로젝트 | `#recommend` | 추천 프로젝트 탐색 및 참여 요청 (중간고사) |
| 팀원 모집 등록 | `#recruit` | 모집 공고 등록 폼 + 내가 등록한 공고 목록 (9·10주차) |
| 문의하기 | `#contact` | 서비스 문의 및 제휴 |

### 현재 위치 표시 방식 (`script.js` 10주차 영역)
- 현재 메뉴는 **실제 화면 위치**를 기준으로 계산합니다(`updateCurrentFromScroll()`). 고정 헤더 바로 아래를 지난 마지막 섹션이 현재 위치이고, 페이지 맨 아래에 닿으면 "문의하기"가 현재 위치가 됩니다.
- **메뉴 클릭**: 누른 메뉴를 바로 표시합니다. 부드럽게 스크롤되는 동안에는 중간 섹션 메뉴로 깜박이지 않도록 잠시 고정하고, 스크롤이 끝나면(`scrollend`) 실제 위치로 다시 맞춥니다.
- **새로고침**: 페이지를 불러올 때와 `load` 시점에 다시 계산합니다. 그래서 `#recruit`가 붙은 주소로 새로고침하거나 스크롤 위치가 복원돼도 표시가 맞습니다.
- **뒤로 가기·앞으로 가기**: `hashchange`, `popstate` 후에 다시 계산합니다.
- 고정 헤더에 섹션 제목이 가리지 않도록 헤더 높이를 CSS 변수(`--header-h`)로 넘겨 `scroll-margin-top`에 사용합니다.

### 필터 기준과 결과 안내
- **기준**: 공고의 진행 방식(`mode`)입니다. 각 버튼 옆에 해당하는 공고 수를 숫자로 표시합니다.
- **선택 표시**: 선택한 버튼만 파란 배경, `✔` 표시, `aria-pressed="true"`가 되고, 나머지는 모두 `false`입니다. 목록도 함께 바뀝니다.
- **결과 수**: "전체 공고 3개를 표시하고 있습니다." 또는 "전체 3개 중 ‘온라인’ 공고 2개를 표시하고 있습니다."
- **빈 결과 두 가지 구분**

| 상황 | 안내 | 다음 행동 버튼 |
| :--- | :--- | :--- |
| 등록된 공고가 하나도 없음 | 📭 아직 등록한 모집 공고가 없습니다. | [공고 작성하러 가기], [예시 공고 3개 불러오기] |
| 공고는 있지만 선택한 방식의 공고가 없음 | 🔍 ‘온·오프라인 혼합’ 방식으로 등록된 공고가 없습니다. | [전체 공고 보기] |

- 폼으로 새 공고를 등록하면 방금 등록한 공고가 보이도록 필터가 "전체"로 돌아갑니다.

### 모바일 메뉴 (768px 이하)
- 메뉴가 접힌 상태로 시작하고, 헤더에는 로고와 [☰ 메뉴 열기] 버튼만 보입니다.
- 버튼을 누르면 메뉴가 펼쳐지고 버튼이 [✕ 메뉴 닫기], `aria-expanded="true"`로 바뀝니다. 다시 누르면 접히고 `false`가 됩니다.
- 메뉴에서 목적지를 누르면 해당 섹션으로 이동하면서 메뉴가 닫힙니다. Esc 키로도 닫힙니다.
- 창을 넓히면 메뉴 열림 상태가 초기화되고, 넓은 화면에서는 버튼이 숨겨지고 메뉴가 한 줄로 표시됩니다.

## ★ 9주차: 팀원 모집 공고 등록 폼 (입력 폼 추가)

### 이번 주 추가·수정한 기능
지금까지는 지원자 쪽 기능(매칭 신청, 참여 요청)만 있었습니다. 그래서 DevBridge의 또 다른 주요 사용자인 **팀 리더가 모집 공고를 등록하는 폼**(`#recruit` 섹션, 메뉴의 "팀원 모집 등록")을 새로 추가했습니다. 등록한 공고는 브라우저 저장소(localStorage)에 저장되어 새로고침해도 "내가 등록한 모집 공고" 목록에 남습니다.

- 텍스트 입력(프로젝트명, 모임 지역, 소개, 이메일), 선택 요소(분야 select, 포지션 체크박스, 진행 방식 라디오, 마감일 date)로 구성했습니다.
- 모든 입력에 `label`을 연결하고, 항목 아래 도움말(`.field-help`)과 상태 문구(`.field-msg`)를 `aria-describedby`로 연결했습니다.

### 입력 조건
| 항목 | 조건 | 오류 시 안내 예시 |
| :--- | :--- | :--- |
| 프로젝트명 * | 5~30자 | `3 / 30자 · ✖ 5자 이상 입력해 주세요. (2자 더 필요)` |
| 프로젝트 분야 * | 선택 필수 | `✖ 프로젝트 분야를 선택해 주세요.` |
| 모집 포지션 * | 1개 이상 체크 | `✖ 모집할 포지션을 1개 이상 체크해 주세요.` |
| 진행 방식 * | 라디오 (기본: 온라인) | - |
| 모임 지역 * (조건부) | 2자 이상 | `✖ 오프라인 모임 지역을 입력해 주세요.` |
| 오프라인 모임 주기 * (조건부) | 선택 필수 | `✖ 오프라인 모임 주기를 선택해 주세요.` |
| 모집 마감일 * (조건부) | 오늘 이후 날짜 | `✖ 지난 날짜는 선택할 수 없습니다. 오늘 이후 날짜를 골라 주세요.` |
| 프로젝트 소개 * | 30~300자 | `✖ 30자 이상 입력해 주세요. (N자 더 필요) …` |
| 팀 리더 연락 이메일 * | 이메일 형식 | `✖ 이메일 형식이 올바르지 않습니다. @와 도메인을 포함해 주세요.` |

### 조건부 입력
- **진행 방식** 라디오에서 `오프라인` 또는 `온·오프라인 혼합`을 고르면 모임 지역과 모임 주기 영역이 나타나고 `disabled`가 해제됩니다. `온라인`으로 바꾸면 영역이 숨겨지고 다시 `disabled`가 됩니다.
- **모집 마감일 지정하기** 체크박스를 켜면 마감일 입력이 나타나고 활성화됩니다. 끄면 숨겨지고 `disabled`가 되며, 공고는 "상시 모집"으로 등록됩니다.
- 숨겨진(disabled) 항목은 검증과 제출 값에서 빠집니다. (`script.js`의 `updateConditionalAreas()`, `isFieldActive()`)

### 입력 상태와 피드백
- 프로젝트명과 소개는 입력하는 동안 `글자 수 / 최대 글자 수`와 조건 충족 여부가 바로 표시됩니다.
- 상태는 색과 문구로 함께 구분합니다.
  - 대기: 회색, 예) `3 / 30자 · 5자 이상 입력해 주세요`
  - 충족: 초록, `✔ 조건 충족`
  - 오류: 빨강, `✖ 문제 + 수정 방법`
- 오류 문구는 입력 후 칸을 벗어났거나 제출을 시도했을 때부터 보입니다. 올바르게 고치면 그 자리에서 `✔ 조건 충족`으로 바뀌고, 위쪽 오류 요약 목록에서도 사라집니다.

### 폼 제출과 결과 처리 (`script.js`의 `recruitForm.addEventListener('submit', …)`)
1. **조건 미충족**: `event.preventDefault()`로 제출을 막습니다. 폼 위에 "수정이 필요한 항목" 요약 목록을 띄우고, 항목을 누르면 해당 입력칸으로 이동합니다.
2. **제출 중**: 버튼이 `등록 중…`으로 바뀌고 [모집 공고 등록하기]와 [다시 작성] 버튼이 `disabled`가 됩니다. "⏳ 모집 공고를 등록하는 중입니다…" 문구가 표시되고, 이 상태에서는 다시 눌러도 중복 등록되지 않습니다. 서버 대신 1.2초 지연(`setTimeout`)으로 처리합니다.
3. **실패**: 입력한 내용은 그대로 두고 버튼을 다시 활성화해 재시도할 수 있게 합니다.
   - 이미 같은 프로젝트명(대소문자 무시)으로 저장된 공고가 있으면 "❌ 등록 실패: … 프로젝트명만 바꿔 다시 등록해 주세요."를 표시하고 프로젝트명 칸으로 이동합니다. (`duplicated` 검사 부분)
   - `localStorage` 저장 중 오류(저장 공간 부족, 저장 차단)가 나면 `try…catch`로 잡아 실패 안내를 표시합니다.
4. **성공**: 폼을 숨기고 "✅ 모집 공고가 등록되었습니다!"와 함께 입력한 내용 요약표를 보여 줍니다. "내가 등록한 모집 공고" 목록과 개수도 갱신됩니다.
5. **다시 작성 / 새 공고 작성하기**: 입력값, 상태 문구, 오류 요약, 조건부 영역(숨김 + disabled), 버튼 문구와 활성 상태를 모두 처음으로 되돌립니다. (`resetRecruitForm()`)

## 1. 서비스 소개 및 사용자 정의
- **서비스명**: DevBridge (데브브릿지)
- **서비스 목적**: 사이드 프로젝트를 시작하기 어려운 개발자에게 기술 스택과 관심사에 맞는 프로젝트와 팀원을 추천하고 연결해 주는 플랫폼.
- **주요 사용자**: 새 프로젝트에 합류하고 싶거나 함께할 팀을 찾는 주니어 개발자 및 협업 희망자.
- **사용자 목표**: 내 포지션·관심 분야에 맞는 팀을 찾아 **실제로 팀에 합류 요청을 보내는 것**.
- **주요 행동**: 매칭 신청(포지션·분야·연락처 등록) → 추천 프로젝트 탐색 → 참여 요청 보내기 / 관리.

## 2. 7주차 결과물에서 새로 추가한 기능 (중간고사)

> 7주차 4단계 매칭 신청 위저드의 **끝(4단계 접수 완료)** 에 이어서, 신청 때 고른 포지션·분야를 기준으로 **추천 프로젝트를 검색·필터링하고, 원하는 팀에 자기소개와 함께 참여 요청을 보내고, 보낸 요청을 취소할 수 있는 "추천 프로젝트 탐색 및 참여 요청" 경로**를 추가했습니다.

7주차에는 "신청서 접수"에서 흐름이 끝났지만, 사용자의 실제 목표는 팀에 합류하는 것이므로 접수 다음 행동(팀 고르기 → 합류 요청)을 이어 붙였습니다.

### 7주차 흐름과의 연결 지점
| 위치 | 연결 방식 |
| :--- | :--- |
| 위저드 4단계(접수 완료) | **[내 조건에 맞는 추천 프로젝트 보기]** 버튼 → 추천 영역으로 이동 |
| 위저드 → 추천 영역 | 1·2단계에서 선택/입력한 **포지션, 관심 분야, 이름, 이메일**이 추천 조건 칩, 필터 기준, 요청서, 성공 안내에 반영 |
| 신청 전 추천 영역 | 잠금 상태 + **[매칭 신청하러 가기]** 버튼 |
| 위저드 [처음부터 다시 신청하기] | 추천 필터·요청서·요청 목록까지 모두 초기화하고 다시 잠금 |

### 7주차와 구별되는 새 요소
- 검색어 입력(`input`) + 체크박스 필터 2개(`change`)로 **실시간 목록 필터링** 및 결과 개수 표시
- 프로젝트별 **상태에 따른 버튼 분기**: 참여 요청하기 / 요청 완료(응답 대기) / 모집 마감 / 내 포지션 모집 없음
- **검색 결과 없음** 상태와 복구 행동(검색어 지우기, 모든 분야 보기)
- 요청서 작성: 참여 가능 시간 선택 + 자기소개 글자 수 **실시간 카운터**(20자 미만 빨강, 이상 초록)
- **동시 요청 최대 3개** 제한
- 보낸 요청 **목록 관리와 2단계 취소 확인**(요청 취소 → 정말 취소할까요? → 네 / 요청 유지)

- 요청서 패널을 열고 닫아도 위에서 입력한 검색어·필터 값은 그대로 유지됩니다.

- [처음부터 다시 신청하기]는 해당 흐름 전체 상태를 초기화합니다.

## 4. 구현 과정
1. **기능 정하기**: 7주차 흐름이 "신청서 접수"에서 끝나 사용자의 실제 목표(팀 합류)까지 이어지지 않는다는 점을 확인하고, 접수 완료 다음 행동으로 "추천 프로젝트 탐색 → 참여 요청 → 요청 관리/취소"를 정했습니다.
2. **HTML 구조 추가**: `#recommend` 섹션에 잠금 안내, 조건 칩, 검색/필터, 카드 목록, 결과 없음 박스, 요청서 패널, 알림, 내 요청 목록 영역을 만들고, 위저드 4단계에 이동 버튼을 연결했습니다.
3. **상태와 데이터 설계**: 프로젝트 8개 데이터(`projects`)와 검색어·필터·선택 프로젝트·요청 목록을 담는 `recommendState`를 만들고, 7주차 `flowState`의 포지션·분야·이름·이메일을 그대로 가져다 쓰도록 했습니다.
4. **이벤트와 조건 연결**: 검색(`input`), 필터(`change`), 요청하기·보내기·작성 취소·요청 취소(`click`)에 조건 검사(결과 0개, 모집 마감, 포지션 불일치, 시간 미선택, 20자 미만, 요청 3개 초과)를 붙이고, 결과에 따라 `renderProjects()`·`renderRequests()`로 화면을 다시 그리게 했습니다.
5. **초기화 연결**: 위저드 접수 시 추천 영역 잠금 해제, [처음부터 다시 신청하기] 시 추천 영역 상태까지 초기화되도록 연결했습니다.
6. **CSS 상태·반응형**: 카드·알림·카운터 상태 클래스를 만들고, 768px 이하에서 카드 1열과 버튼 100% 너비로 바뀌게 했습니다.
7. **오류 수정 및 확인**: 테스트 중 7주차 `script.js`의 `--` 문법 오류로 스크립트 전체가 실행되지 않던 문제를 찾아 고쳤고, 아래 6장의 경로를 데스크톱과 모바일 너비에서 확인했습니다.

| 11 | 정상 | 시간 선택 + 20자 이상 작성 후 전송 | 성공 안내(신청 이메일 포함), 카드 "요청 완료", 목록 1 / 3 | 통과 |
| 12 | 제한 | 요청 3개 보낸 뒤 4번째 [참여 요청하기] | 요청서 안 열림, "최대 3개" 빨간 안내, 개수 배지 빨강 | 통과 |
| 13 | 취소 → 유지 | [요청 취소] → [요청 유지] | 확인 문구 사라지고 요청 3개 유지 | 통과 |
| 14 | 취소 | [요청 취소] → [네, 취소합니다] | 목록 2개, 해당 카드 다시 [참여 요청하기] 활성 | 통과 |
| 15 | 초기화 | 위저드 [처음부터 다시 신청하기] | 위저드 값 + 검색어·필터·요청 목록 초기화, 추천 영역 다시 잠금 | 통과 |

위 15개 경로는 헤드리스 Chrome에서 같은 순서로 자동 클릭·입력하는 스크립트로도 다시 실행해 모두 통과했습니다.

### 6-2. 반응형 확인
- **1100px (데스크톱)**: 필터가 한 줄(검색창 + 체크박스 2개)로, 프로젝트 카드는 2열 그리드로 배치. 요청서의 [작성 취소]/[참여 요청 보내기]는 좌우 분할.
