## ★ 9주차: 팀원 모집 공고 등록 폼 (입력 폼 추가)

### 이번 주 추가·수정한 기능
지금까지는 지원자 쪽 기능(매칭 신청, 참여 요청)만 있었습니다. 그래서 DevBridge의 또 다른 주요 사용자인 **팀 리더가 모집 공고를 등록하는 폼**(`#recruit` 섹션, 메뉴의 "팀원 모집 등록")을 새로 추가했습니다. 등록한 공고는 브라우저 저장소(localStorage)에 저장되어 새로고침해도 "내가 등록한 모집 공고" 목록에 남습니다.

- 텍스트 입력(프로젝트명, 모임 지역, 소개, 이메일), 선택 요소(분야 select, 포지션 체크박스, 진행 방식 라디오, 마감일 date)로 구성했습니다.
- 모든 입력에 `label`을 연결하고, 항목 아래 도움말(`.field-help`)과 상태 문구(`.field-msg`)를 `aria-describedby`로 연결했습니다.

### 입력 조건
| 항목 | 조건 | 오류 시 안내 예시 |
| :--- | :--- | :--- |
| 프로젝트명 * | 5~30자 | `3 / 30자 · ✖ 5자 이상 입력해 주세요. (2자 더 필요)` |
| 프로젝트 분야 * | 선택 필수 | `✖ 프로젝트 분야를 선택해 주세요.` |
| 모집 포지션 * | 1개 이상 체크 | `✖ 모집할 포지션을 1개 이상 체크해 주세요.` |
| 진행 방식 * | 라디오 (기본: 온라인) | - |
| 모임 지역 * (조건부) | 2자 이상 | `✖ 오프라인 모임 지역을 입력해 주세요.` |
| 오프라인 모임 주기 * (조건부) | 선택 필수 | `✖ 오프라인 모임 주기를 선택해 주세요.` |
| 모집 마감일 * (조건부) | 오늘 이후 날짜 | `✖ 지난 날짜는 선택할 수 없습니다. 오늘 이후 날짜를 골라 주세요.` |
| 프로젝트 소개 * | 30~300자 | `✖ 30자 이상 입력해 주세요. (N자 더 필요) …` |
| 팀 리더 연락 이메일 * | 이메일 형식 | `✖ 이메일 형식이 올바르지 않습니다. @와 도메인을 포함해 주세요.` |

### 조건부 입력
- **진행 방식** 라디오에서 `오프라인` 또는 `온·오프라인 혼합`을 고르면 모임 지역과 모임 주기 영역이 나타나고 `disabled`가 해제됩니다. `온라인`으로 바꾸면 영역이 숨겨지고 다시 `disabled`가 됩니다.
- **모집 마감일 지정하기** 체크박스를 켜면 마감일 입력이 나타나고 활성화됩니다. 끄면 숨겨지고 `disabled`가 되며, 공고는 "상시 모집"으로 등록됩니다.
- 숨겨진(disabled) 항목은 검증과 제출 값에서 빠집니다. (`script.js`의 `updateConditionalAreas()`, `isFieldActive()`)

### 입력 상태와 피드백
- 프로젝트명과 소개는 입력하는 동안 `글자 수 / 최대 글자 수`와 조건 충족 여부가 바로 표시됩니다.
- 상태는 색과 문구로 함께 구분합니다.
  - 대기: 회색, 예) `3 / 30자 · 5자 이상 입력해 주세요`
  - 충족: 초록, `✔ 조건 충족`
  - 오류: 빨강, `✖ 문제 + 수정 방법`
- 오류 문구는 입력 후 칸을 벗어났거나 제출을 시도했을 때부터 보입니다. 올바르게 고치면 그 자리에서 `✔ 조건 충족`으로 바뀌고, 위쪽 오류 요약 목록에서도 사라집니다.

### 폼 제출과 결과 처리 (`script.js`의 `recruitForm.addEventListener('submit', …)`)
1. **조건 미충족**: `event.preventDefault()`로 제출을 막습니다. 폼 위에 "수정이 필요한 항목" 요약 목록을 띄우고, 항목을 누르면 해당 입력칸으로 이동합니다.
2. **제출 중**: 버튼이 `등록 중…`으로 바뀌고 [모집 공고 등록하기]와 [다시 작성] 버튼이 `disabled`가 됩니다. "⏳ 모집 공고를 등록하는 중입니다…" 문구가 표시되고, 이 상태에서는 다시 눌러도 중복 등록되지 않습니다. 서버 대신 1.2초 지연(`setTimeout`)으로 처리합니다.
3. **실패**: 입력한 내용은 그대로 두고 버튼을 다시 활성화해 재시도할 수 있게 합니다.
   - 이미 같은 프로젝트명(대소문자 무시)으로 저장된 공고가 있으면 "❌ 등록 실패: … 프로젝트명만 바꿔 다시 등록해 주세요."를 표시하고 프로젝트명 칸으로 이동합니다. (`duplicated` 검사 부분)
   - `localStorage` 저장 중 오류(저장 공간 부족, 저장 차단)가 나면 `try…catch`로 잡아 실패 안내를 표시합니다.
4. **성공**: 폼을 숨기고 "✅ 모집 공고가 등록되었습니다!"와 함께 입력한 내용 요약표를 보여 줍니다. "내가 등록한 모집 공고" 목록과 개수도 갱신됩니다.
5. **다시 작성 / 새 공고 작성하기**: 입력값, 상태 문구, 오류 요약, 조건부 영역(숨김 + disabled), 버튼 문구와 활성 상태를 모두 처음으로 되돌립니다. (`resetRecruitForm()`)

## 1. 서비스 소개 및 사용자 정의
- **서비스명**: DevBridge (데브브릿지)
- **서비스 목적**: 사이드 프로젝트를 시작하기 어려운 개발자에게 기술 스택과 관심사에 맞는 프로젝트와 팀원을 추천하고 연결해 주는 플랫폼.
- **주요 사용자**: 새 프로젝트에 합류하고 싶거나 함께할 팀을 찾는 주니어 개발자 및 협업 희망자.
- **사용자 목표**: 내 포지션·관심 분야에 맞는 팀을 찾아 **실제로 팀에 합류 요청을 보내는 것**.
- **주요 행동**: 매칭 신청(포지션·분야·연락처 등록) → 추천 프로젝트 탐색 → 참여 요청 보내기 / 관리.

## 2. 7주차 결과물에서 새로 추가한 기능 (중간고사)

> 7주차 4단계 매칭 신청 위저드의 **끝(4단계 접수 완료)** 에 이어서, 신청 때 고른 포지션·분야를 기준으로 **추천 프로젝트를 검색·필터링하고, 원하는 팀에 자기소개와 함께 참여 요청을 보내고, 보낸 요청을 취소할 수 있는 "추천 프로젝트 탐색 및 참여 요청" 경로**를 추가했습니다.

7주차에는 "신청서 접수"에서 흐름이 끝났지만, 사용자의 실제 목표는 팀에 합류하는 것이므로 접수 다음 행동(팀 고르기 → 합류 요청)을 이어 붙였습니다.

### 7주차 흐름과의 연결 지점
| 위치 | 연결 방식 |
| :--- | :--- |
| 위저드 4단계(접수 완료) | **[내 조건에 맞는 추천 프로젝트 보기]** 버튼 → 추천 영역으로 이동 |
| 위저드 → 추천 영역 | 1·2단계에서 선택/입력한 **포지션, 관심 분야, 이름, 이메일**이 추천 조건 칩, 필터 기준, 요청서, 성공 안내에 반영 |
| 신청 전 추천 영역 | 잠금 상태 + **[매칭 신청하러 가기]** 버튼 |
| 위저드 [처음부터 다시 신청하기] | 추천 필터·요청서·요청 목록까지 모두 초기화하고 다시 잠금 |

### 7주차와 구별되는 새 요소
- 검색어 입력(`input`) + 체크박스 필터 2개(`change`)로 **실시간 목록 필터링** 및 결과 개수 표시
- 프로젝트별 **상태에 따른 버튼 분기**: 참여 요청하기 / 요청 완료(응답 대기) / 모집 마감 / 내 포지션 모집 없음
- **검색 결과 없음** 상태와 복구 행동(검색어 지우기, 모든 분야 보기)
- 요청서 작성: 참여 가능 시간 선택 + 자기소개 글자 수 **실시간 카운터**(20자 미만 빨강, 이상 초록)
- **동시 요청 최대 3개** 제한
- 보낸 요청 **목록 관리와 2단계 취소 확인**(요청 취소 → 정말 취소할까요? → 네 / 요청 유지)

## 3. 새 기능의 사용자 행동 · 조건 · 반응 · 다음 행동

| 사용자 행동 | 이벤트 | 확인할 조건 | 화면 반응 | 다음 행동 |
| :--- | :--- | :--- | :--- | :--- |
| 매칭 신청 전 추천 영역 확인 | (초기 상태) | `flowState.submitted === false` | 🔒 잠금 안내 표시, 목록 숨김 | [매칭 신청하러 가기] |
| 4단계에서 [내 조건에 맞는 추천 프로젝트 보기] 클릭 | `click` | 접수 완료 여부 | 잠금 해제, 이름·포지션·분야 칩 표시, "내 관심 분야만 보기"가 켜진 추천 목록 | 검색하거나 카드 선택 |
| 검색어 입력 | `input` | 프로젝트명·기술 스택에 검색어 포함 여부(대소문자 무시) | 목록과 "조건에 맞는 프로젝트 N개" 즉시 갱신 | 카드 선택 |
| 필터 체크박스 변경 | `change` | 분야 일치 / 포지션 모집 여부 | 목록 즉시 갱신, 내 포지션 태그는 초록색 강조 | 카드 선택 |
| 조건에 맞는 프로젝트가 없음 | `input`/`change` | 필터 결과 0개 | **결과 없음** 안내 박스 표시 | [검색어 지우기] 또는 [모든 분야 프로젝트 보기] |
| 마감됐거나 내 포지션이 없는 카드 | (렌더링) | `slots === 0` / 포지션 미포함 | 버튼 비활성 + "모집 마감" / "내 포지션 모집 없음" 문구 | 다른 카드 선택 |
| [참여 요청하기] 클릭 | `click` | 보낸 요청 수 < 3 | 카드 초록 테두리 강조, 요청서 패널 열림(프로젝트명·포지션 자동 반영) | 시간 선택, 자기소개 작성 |
| 요청이 이미 3개인데 [참여 요청하기] 클릭 | `click` | 보낸 요청 수 ≥ 3 | 빨간 안내: "최대 3개까지… 기존 요청을 취소한 뒤 다시 시도" | 목록에서 요청 취소 |
| 자기소개 입력 | `input` | 현재 글자 수 ≥ 20 | 카운터 `N / 200자` 실시간 갱신(빨강 → 초록) | 계속 작성 |
| 시간 미선택 후 [참여 요청 보내기] | `click` | 참여 가능 시간 값이 빈 값 | "주당 참여 가능 시간을 선택해 주세요." + 선택창 포커스 | 시간 선택 |
| 20자 미만 작성 후 [참여 요청 보내기] | `click` | `message.trim().length < 20` | "20자 이상 적어 주세요. (현재 N자, M자 더 필요) 사용해 본 기술이나 참여 이유를 적으면 좋아요." + 입력창 포커스 | 내용 보충 |
| 조건 충족 후 [참여 요청 보내기] | `click` | 시간 선택 && 20자 이상 | ✅ "‘프로젝트’ 팀에 참여 요청을 보냈습니다. 팀 리더가 수락하면 (신청 이메일)로 알려 드립니다." 패널 닫힘, 카드 "요청 완료(응답 대기)", 요청 목록에 추가, `N / 3` 갱신 | 다른 프로젝트 요청 / 요청 관리 |
| 요청서에서 [작성 취소] 클릭 | `click` | - | 패널 닫힘, 요청은 추가되지 않음, "요청서 작성을 취소했습니다" 안내 | 다른 프로젝트 선택 |
| 목록에서 [요청 취소] 클릭 | `click` | - | "정말 요청을 취소할까요?" + [네, 취소합니다] / [요청 유지] | 확정 또는 유지 |
| [요청 유지] 클릭 | `click` | - | 원래 상태로 돌아감, 요청 유지 | - |
| [네, 취소합니다] 클릭 | `click` | - | 목록에서 삭제, 카드 버튼이 다시 [참여 요청하기]로 복귀, 개수 감소, 취소 안내 | 다른 팀에 다시 요청 |
| 위저드 [처음부터 다시 신청하기] | `click` | 초기화 요청 | 위저드 + 추천 영역 상태(검색어, 필터, 요청서, 요청 목록) 모두 초기화 후 잠금 | 다시 매칭 신청 |

**값 유지 / 초기화 규칙**
- 요청서 패널을 열고 닫아도 위에서 입력한 검색어·필터 값은 그대로 유지됩니다.
- 새 프로젝트의 요청서를 열 때는 이전 작성 내용을 비우고 새로 시작합니다(다른 팀에 같은 글이 잘못 전송되지 않도록).
- [처음부터 다시 신청하기]는 해당 흐름 전체 상태를 초기화합니다.

## 4. 구현 과정
1. **기능 정하기**: 7주차 흐름이 "신청서 접수"에서 끝나 사용자의 실제 목표(팀 합류)까지 이어지지 않는다는 점을 확인하고, 접수 완료 다음 행동으로 "추천 프로젝트 탐색 → 참여 요청 → 요청 관리/취소"를 정했습니다.
2. **HTML 구조 추가**: `#recommend` 섹션에 잠금 안내, 조건 칩, 검색/필터, 카드 목록, 결과 없음 박스, 요청서 패널, 알림, 내 요청 목록 영역을 만들고, 위저드 4단계에 이동 버튼을 연결했습니다.
3. **상태와 데이터 설계**: 프로젝트 8개 데이터(`projects`)와 검색어·필터·선택 프로젝트·요청 목록을 담는 `recommendState`를 만들고, 7주차 `flowState`의 포지션·분야·이름·이메일을 그대로 가져다 쓰도록 했습니다.
4. **이벤트와 조건 연결**: 검색(`input`), 필터(`change`), 요청하기·보내기·작성 취소·요청 취소(`click`)에 조건 검사(결과 0개, 모집 마감, 포지션 불일치, 시간 미선택, 20자 미만, 요청 3개 초과)를 붙이고, 결과에 따라 `renderProjects()`·`renderRequests()`로 화면을 다시 그리게 했습니다.
5. **초기화 연결**: 위저드 접수 시 추천 영역 잠금 해제, [처음부터 다시 신청하기] 시 추천 영역 상태까지 초기화되도록 연결했습니다.
6. **CSS 상태·반응형**: 카드·알림·카운터 상태 클래스를 만들고, 768px 이하에서 카드 1열과 버튼 100% 너비로 바뀌게 했습니다.
7. **오류 수정 및 확인**: 테스트 중 7주차 `script.js`의 `--` 문법 오류로 스크립트 전체가 실행되지 않던 문제를 찾아 고쳤고, 아래 6장의 경로를 데스크톱과 모바일 너비에서 확인했습니다.
